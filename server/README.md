# Поставки Ozon на сервере (OpenMediaVault + Docker + Tailscale)

Серверная версия — та же программа, что и `.exe`, только запущенная в Docker-контейнере.
Образ собирается в GitHub Actions при каждом выпуске: `ghcr.io/digushok/postavka:latest`
и `ghcr.io/digushok/postavka:<версия>`.

Отличия от Windows-версии:

- открывается по адресу `https://kucha.tailc40790.ts.net:8443/` с любого устройства в Tailscale;
- работает круглосуточно, браузер не нужен держать открытым;
- магазины общие для всех, а выбранный магазин у каждого браузера свой
  (двое могут одновременно работать с разными магазинами);
- нет кнопок «Открыть папку», «Найти старые настройки» и «Закрыть программу» —
  этикетки и лист сборки открываются и скачиваются по ссылкам на странице партии.

## 1. Папка для данных

На сервере: `/srv/dev-disk-by-uuid-9e04cc1f-10cc-4f8f-a469-0c7579a5c598/config/postavka/data`.
Отдельная от Ozon rFBS (`config/rfbs/data`), чтобы данные двух программ не смешались.
Создайте её (в OMV — через общую папку SMB или консоль):

```bash
mkdir -p /srv/dev-disk-by-uuid-9e04cc1f-10cc-4f8f-a469-0c7579a5c598/config/postavka/data
```

## 2. Перенос данных с Windows

1. На Windows закройте программу (кнопка ⏻ вверху), чтобы во время копирования ничего не менялось.
2. Откройте папку `%APPDATA%\Поставки Ozon\data` (вставьте этот путь в адресную строку Проводника).
3. Скопируйте **всё её содержимое** в папку `config/postavka/data` на сервере (через общую папку SMB).
   Там `profiles.json` (магазины и ключи API) и `shops\` (партии, этикетки).

Если контейнер уже запущен — после копирования перезапустите его (в OMV кнопки Down, затем Up).

Только настройки без партий можно перенести и иначе: в Windows-версии «Настройки → Сохранить копию настроек»,
на сервере «Загрузить из файла».

## 3. Запуск в OpenMediaVault

Services → Compose → Files → «+» (Create):

- Name: `postavka`
- File: содержимое [`compose.yml`](compose.yml)

Сохраните, выделите файл и нажмите **Up**. В Logs должна появиться строка
`Поставки Ozon 1.7.9 (сервер) слушают http://0.0.0.0:8765/, данные: /data`.

Образ собран для amd64, работает на Pentium E2180.

## 4. Tailscale (правило Ozon rFBS не трогаем)

На `https://kucha.tailc40790.ts.net/` (порт 443) уже работает Ozon rFBS. **`tailscale serve reset` не выполнять** —
он удалит это правило. Поставки вешаются на отдельный HTTPS-порт 8443 — правило добавляется к существующим:

```bash
docker exec tailscale tailscale serve --bg --https=8443 http://127.0.0.1:8767
```

Проверка — должны быть видны оба правила (443 → 192.168.1.88:8766 и 8443 → 127.0.0.1:8767):

```bash
docker exec tailscale tailscale serve status
```

Программа откроется по адресу **https://kucha.tailc40790.ts.net:8443/**.
Если когда-нибудь понадобится убрать только это правило:

```bash
docker exec tailscale tailscale serve --https=8443 off
```

## Обновление

Новая версия появляется через несколько минут после выпуска. Программа сама покажет «доступна X.Y.Z»
внизу страницы. В OMV: Compose → Files → `postavka` → **Pull**, затем **Up**. Данные не трогаются.
Перед обновлением лучше дождаться, пока закончится создание поставок
(незавершённую партию можно продолжить кнопкой на её странице).

Вернуться на прошлую версию: в файле замените `:latest` на номер, например `:1.7.9`, и нажмите Up.

### Старые версии занимают место

После каждого Pull прошлый образ остаётся на диске (≈150 МБ). Когда их накапливается много,
Docker работает медленнее. Раз в несколько обновлений удаляйте неиспользуемые:
OMV → Compose → Images → строки с тегом `<none>` → Delete, или в консоли сервера

```bash
docker image prune -f
```

Запущенные контейнеры и их образы команда не трогает, данные программы — тоже.

## Резервная копия

Всё, что нужно сохранить, — папка `config/postavka/data`. Её удобно включить в резервное копирование OMV.

## Если образ не скачивается

`docker compose pull` отвечает `denied` или `unauthorized` — значит, пакет в GitHub ещё закрытый.
Владелец репозитория открывает его один раз: GitHub → профиль → Packages → `postavka` →
Package settings → Change visibility → Public.
