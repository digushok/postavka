# Поставки Ozon на сервере (OpenMediaVault + Docker + Tailscale)

Серверная версия — та же программа, что и `.exe`, только запущенная в Docker-контейнере.
Образ собирается в GitHub Actions при каждом выпуске: `ghcr.io/digushok/postavka:latest`
и `ghcr.io/digushok/postavka:<версия>`.

Отличия от Windows-версии:

- открывается по адресу `https://kucha.tailc40790.ts.net/` с любого устройства в Tailscale;
- работает круглосуточно, браузер не нужен держать открытым;
- магазины общие для всех, а выбранный магазин у каждого браузера свой
  (двое могут одновременно работать с разными магазинами);
- нет кнопок «Открыть папку», «Найти старые настройки» и «Закрыть программу» —
  этикетки и лист сборки открываются и скачиваются по ссылкам на странице партии.

## 1. Первый запуск

Папка для программы на сервере, например на диске данных OMV
(подставьте свой путь — в OMV это обычно `/srv/dev-disk-by-uuid-…/`):

```bash
mkdir -p /srv/<диск>/postavka/data
cd /srv/<диск>/postavka
curl -fsSLO https://raw.githubusercontent.com/digushok/postavka/main/server/compose.yml
```

Если используете плагин **Compose** в веб-интерфейсе OMV — создайте там файл
и вставьте содержимое [`compose.yml`](compose.yml), путь `./data` замените на полный путь к папке данных.

Данные с Windows-компьютера переносятся до запуска — см. раздел 2. Затем:

```bash
docker compose up -d
docker compose logs -f
```

В журнале должна появиться строка `Поставки Ozon 1.7.8 (сервер) слушают …`.

## 2. Перенос данных с Windows

1. На Windows закройте программу (кнопка ⏻ вверху), чтобы во время копирования ничего не менялось.
2. Откройте папку `%APPDATA%\Поставки Ozon\data` (вставьте этот путь в адресную строку Проводника).
3. Скопируйте **всё её содержимое** в папку `data` на сервере — через общую папку SMB в OMV или `scp`.
   В ней `profiles.json` (магазины и ключи API) и `shops\` (партии, этикетки).
4. Запустите контейнер (`docker compose up -d`) или перезапустите, если он уже работал
   (`docker compose restart`).

Только настройки без партий можно перенести и иначе: в Windows-версии «Настройки → Сохранить копию настроек»,
на сервере «Загрузить из файла».

## 3. Tailscale

Контейнер слушает только `127.0.0.1:8766` — из домашней сети напрямую он не виден,
потому что входа по паролю у программы нет, а в настройках лежат API-ключи.
Доступ — только через Tailscale. Перенаправьте `tailscale serve` на этот адрес
(Tailscale работает в контейнере с `network_mode: host`, поэтому `127.0.0.1` сервера ему доступен):

```bash
docker exec tailscale tailscale serve reset
```

```bash
docker exec tailscale tailscale serve --bg http://127.0.0.1:8766
```

```bash
docker exec tailscale tailscale serve status
```

Если всё же нужен доступ из домашней сети без Tailscale — в `compose.yml` замените
`"127.0.0.1:8766:8765"` на `"8766:8765"`.

## 4. Обновление

Новая версия появляется в GitHub через несколько минут после выпуска.
Программа сама покажет «доступна X.Y.Z» внизу страницы. Обновить:

```bash
cd /srv/<диск>/postavka && docker compose pull && docker compose up -d
```

Данные в папке `data` при этом не трогаются. Перед обновлением лучше дождаться,
пока закончится создание поставок (незавершённую партию можно продолжить кнопкой на её странице).

Вернуться на прошлую версию: в `compose.yml` замените `:latest` на номер, например `:1.7.8`.

## 5. Резервная копия

Всё, что нужно сохранить, — папка `data`. Её удобно включить в резервное копирование OMV.

## Если образ не скачивается

`docker compose pull` отвечает `denied` или `unauthorized` — значит, пакет в GitHub ещё закрытый.
Владелец репозитория открывает его один раз: GitHub → профиль → Packages → `postavka` →
Package settings → Change visibility → Public.
